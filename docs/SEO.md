# SEO-оптимизация mindtech.kz — отчёт и инструкции

Ветка: `seo/technical-optimization`. На рабочий сервер **ничего не публиковалось**.

## 1. Аудит

### Реальный стек
- Python 3.12, **Django 6.0.2 + Wagtail 7.3 + wagtail-localize 1.13** (RU/KZ/EN через `i18n_patterns`, префиксы `/ru/`, `/kk/`, `/en/`).
- PostgreSQL, whitenoise, waitress за **IIS 10 + ARR** (видно по заголовкам ответа).
- Приложения: `home` (все модели страниц, сниппеты, настройки), `search`.
- Типы страниц: `HomePage`, `ProjectsIndexPage`, `ProjectPage` (StreamField: hero, карточки, шаги, FAQ, галерея…), `DocumentsPage`, `LegalPage`.
- Метатеги выводились вручную в `config/templates/base.html`. Тестов в проекте не было.

### Что теперь работает
- `GET /robots.txt` → 200 `text/plain`: закрыты только `/admin/`, `/django-admin/`, `/contact/submit/`, `/search/`, `/i18n/`; `Clean-param` для Яндекса (UTM, `?sent=`); `Sitemap: https://mindtech.kz/sitemap.xml`. Одна группа `User-agent: *` распространяется на Googlebot, Bingbot, YandexBot и OAI-SearchBot; GPTBot (обучение моделей) тоже не закрыт — см. раздел 8.
- `GET /sitemap.xml` → 200 `application/xml`: опубликованные публичные страницы всех трёх языков, абсолютные HTTPS-адреса, `lastmod` = реальная дата публикации, `xhtml:link hreflang`. Исключены: черновики, noindex, страницы под паролем.
- На каждой странице: один `<title>`, уникальный `description`, `meta robots`, self-canonical без параметров, `hreflang` только для реально существующих переводов + `x-default`, Open Graph и Twitter Card, JSON-LD.
- JSON-LD: `Organization` (название, логотип, адрес «ул. Жамбыла, 42, Караганда, KZ», телефон, email, `areaServed: Kazakhstan`), `WebSite`, `WebPage`/`CollectionPage`, `BreadcrumbList` для вложенных страниц, `Service` для страниц-услуг, `FAQPage` из видимого FAQ-блока. Никаких Review/Rating/Article.
- Предпросмотр, поиск и noindex-страницы получают `noindex, follow`.

- `manage.py check` — без ошибок; `makemigrations --check` — изменений нет.
- `check --deploy` с production-настройками: 2 предупреждения про HSTS/SSL-редирект — они были и до изменений (HTTPS обеспечивает IIS).

## 5. Публикация на сервер

1. Сделайте резервную копию базы PostgreSQL (`pg_dump`).
2. Залейте ветку `seo/technical-optimization` (или смёржите её в `main`) на сервер.
3. Новые зависимости **не нужны** (`requests` уже в `requirements_server.txt`). Если хотите запускать тесты на сервере, установите `beautifulsoup4` — он тоже уже в списке.
4. `python manage.py migrate` — применится `home.0007_seo_fields` (только новые поля со значениями по умолчанию, данные не меняются).
5. `python manage.py collectstatic --noinput` (изменены два CSS-файла).
6. Перезапустите сайт (пул приложений IIS / службу waitress).
7. Посмотрите, что изменит команда: `python manage.py seo_fill_metadata`. Если всё устраивает — `python manage.py seo_fill_metadata --apply`. Команда заполняет только пустые поля, создаёт ревизии (откат через «История» страницы) и пропускает страницы с неопубликованными черновиками. Чтобы заменить и уже заполненные title у «Системной интеграции» и «ИИ-агентов», запустите с `--overwrite` или поправьте вручную в админке.
8. Кеш очищать не нужно (кеширующего слоя нет). Если IIS кеширует ответы, сбросьте его кеш.
9. Проверка после выкладки:
   - https://mindtech.kz/robots.txt и https://mindtech.kz/sitemap.xml открываются (не 404);
   - в исходном коде https://mindtech.kz/ru/ есть `rel="canonical"`, три `hreflang` и `application/ld+json`;
   - https://search.google.com/test/rich-results и https://validator.schema.org/ — вставьте адреса `/ru/` и `/ru/projects/system-integration/`;
   - https://mindtech.kz/kk/ — описание на казахском.
10. IndexNow (по желанию): в `.env` задайте `INDEXNOW_KEY=<32 случайных символа>` и `INDEXNOW_ENABLED=True`, перезапустите сайт и проверьте, что открывается `https://mindtech.kz/<ключ>.txt`.

Важно для IIS: `/robots.txt`, `/sitemap.xml` и `/<ключ>.txt` должны проксироваться в Django. Сейчас IIS отдаёт по этим адресам Django-ответ 404, то есть проксирование уже работает.

## 6. Инструкция для владельца сайта

### Google Search Console — https://search.google.com/search-console
1. Войдите в Google-аккаунт компании → «Добавить ресурс».
2. Выберите тип **«Доменный ресурс»** и введите `mindtech.kz`. Google выдаст TXT-запись — добавьте её в DNS у регистратора домена (это охватит http/https и www). Альтернатива — тип «Ресурс с префиксом URL» `https://mindtech.kz/` + способ «Тег HTML»: скопируйте **только значение `content`** из выданного тега и вставьте в админке: **Настройки → Site branding → «SEO: подтверждение прав…» → Google Search Console** → Сохранить → нажмите «Подтвердить» в Search Console.
3. **Файлы Sitemap** → введите `sitemap.xml` → Отправить.
4. **Проверка URL** → вставьте `https://mindtech.kz/ru/projects/system-integration/` → «Запросить индексирование». Повторите для главных RU/KZ/EN и страницы ИИ-агентов.
5. Через 3–14 дней смотрите отчёты «Страницы» (что проиндексировано и почему нет) и «Эффективность» (запросы и показы).

### Яндекс Вебмастер — https://webmaster.yandex.ru/
1. «Добавить сайт» → `https://mindtech.kz`.
2. Подтверждение «Мета-тег»: значение `content` вставьте в админке в поле **Яндекс Вебмастер** → Сохранить → «Проверить». Или DNS-запись.
3. **Индексирование → Файлы Sitemap** → `https://mindtech.kz/sitemap.xml`.
4. **Индексирование → Переобход страниц** — добавьте главные страницы.
5. **Информация о сайте → Регион сайта** → Караганда (или Казахстан).
6. Проверьте **Индексирование → Анализ robots.txt**.

### Bing Webmaster Tools — https://www.bing.com/webmasters/
1. Войдите и выберите «Импорт из Google Search Console» (быстрее всего) или добавьте сайт вручную.
2. При ручном добавлении: способ «Meta tag», значение `content` → поле **Bing Webmaster Tools** в админке.
3. **Sitemaps** → `https://mindtech.kz/sitemap.xml`.
4. Bing — основной источник данных для ChatGPT Search и Copilot. Если включите IndexNow (раздел 5, п. 10), Bing будет узнавать о новых страницах сразу. Google IndexNow не использует.

Жамбыла, 42, Караганда», телефон +7 708 439 70 98, сайт https://mindtech.kz/ru/. Google попросит подтвердить компанию (видео, звонок или письмо) — это делается только вами.

### Как управлять SEO в админке
- **Страница → вкладка «Продвижение»:**
  - «Слаг» — адрес. Wagtail при смене слага сам создаёт 301-редирект со старого адреса.
  - «Заголовок страницы» — это `<title>`, до ~65 символов.
  - «Описание для поиска» — meta description, 120–160 символов.
  - «SEO: дополнительно»: изображение для соцсетей (1200×630); «Скрыть от поисковых систем (noindex)»; у проектов ещё «Тип страницы для структурированных данных» — выбирайте «Услуга» для страниц-услуг.
  - Пустые поля сайт заполнит сам: название страницы + «| Mind Technology», описание — из описания карточки, вступления или из настроек.
- **Настройки → Site branding:** описания по умолчанию на трёх языках, OG-изображение по умолчанию, данные организации (юр. название, адрес, тип), коды подтверждения поисковых систем.
- **Главная → блок «Услуги» → карточка → «Ссылка на страницу»:** свяжите карточки с соответствующими страницами (например, «Программные решения» → «Системная интеграция»). Это внутренняя ссылка для поисковиков и людей; на сайте появится «Подробнее →».
- Переводы: если KZ/EN-страница синхронизируется через wagtail-localize, правьте её SEO-поля в редакторе перевода. Иначе при следующей синхронизации значения перезапишутся.

## 8. Производительность (рекомендации, не внедрены)
- `logo-mind.png` (241 КБ, 1024×1024) используется как favicon, apple-touch-icon и логотип прелоадера. Лучше сделать уменьшенные копии на 32/180/256 px — экономия ~230 КБ при первом визите.
- `og-cover.png` весит 300 КБ — можно сжать до ~100 КБ без видимой потери.
- Статика отдаётся с `Cache-Control: max-age=60` и без хешей в именах. Включите долгий кеш для `/static/` в IIS или раздачу хешированных файлов через whitenoise.
- Шрифт Inter грузится с Google Fonts блокирующим CSS. Можно оставить или перенести шрифт на свой сервер.
- Внедрено: `loading="lazy"` и `decoding="async"` у изображений ниже первого экрана, `alt` у скриншотов.
